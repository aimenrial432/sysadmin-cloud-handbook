# 03-EC2 (Amazon Elastic Compute Cloud)

## 1. Executive Summary (What is it & Why use it?)
* **One-Sentence Definition:** **Amazon EC2 (Elastic Compute Cloud)** is AWS's core **Infrastructure as a Service (IaaS)** offering that lets you rent resizable virtual servers (EC2 instances) on demand in the cloud.
* **Primary Use Case:** Hosting applications, web servers, backend APIs, batch processing, and custom workloads requiring full OS-level control (Linux, Windows, or macOS).
* **Scope / Responsibility Model:**
  * **Scope:** **Regional** service (instances are launched inside a specific Availability Zone within a Region).
  * **Shared Responsibility:** AWS manages the physical host, hypervisor, and underlying network; **you** manage the guest OS, patches, applications, Security Groups, and data.

## 2. Key Concepts & Architecture

### A. EC2 Ecosystem Components (High-Level)
EC2 is more than just virtual machines—it encompasses a full compute ecosystem:
* **EC2 Instances:** On-demand virtual servers rented from AWS.
* **EBS (Elastic Block Store):** Persistent virtual hard drives attached over the network.
* **ELB (Elastic Load Balancer):** Distributes incoming network traffic across multiple EC2 instances.
* **ASG (Auto Scaling Group):** Automatically scales the number of EC2 instances in or out based on demand.

### B. Instance Configuration Options (Sizing & Hardware)
When provisioning an EC2 instance, you customize:
* **Operating System (AMI):** **Linux** (most common), **Windows**, or **macOS**.
* **Compute & Memory:** Number of virtual CPUs (**vCPU**) and amount of **RAM**.
* **Storage Type:**
  * *Network-attached:* **EBS** (block storage) or **EFS** (shared network file system).
  * *Hardware-attached (ephemeral):* **EC2 Instance Store** (physically attached to the host server for ultra-high IOPS).
* **Networking:** Network card speed (bandwidth) and Public IP assignment.
* **Firewall Rules:** **Security Groups** controlling inbound and outbound traffic.

### C. Bootstrapping with EC2 User Data
* **Definition:** Passing a startup script (**EC2 User Data**) to automate tasks when an instance launches.
* **Execution Behavior:**
  * Runs **only once**—strictly during the **first boot** of the instance (never re-runs on subsequent reboots).
  * Executes with **`root` privileges** (`sudo` rights by default), so commands do not need `sudo` prepended.
* **Common Tasks:** Installing OS updates, installing software packages (e.g., Apache/Nginx), downloading files from the internet, or configuring services.
* **Trade-off:** Adding heavy tasks to User Data increases total instance boot time.

### D. Instance Lifecycle, Networking & Storage Behavior
* **Key Pairs (SSH Authentication):**
  * **`.pem` format:** Standard format for Linux, macOS, and Windows 10/11 (OpenSSH).
  * **`.ppk` format:** Legacy format required for PuTTY on Windows 7/8.
* **Public IPv4 vs. Private IPv4 (Stop/Start Trap):**
  * **Public IPv4:** Assigned dynamically from AWS's public pool. When you **Stop** and **Start** an instance, AWS releases the Public IP and assigns a **new Public IPv4 address** (unless you attach an **Elastic IP**).
  * **Private IPv4:** Remains **static/unchanged** across Stop/Start cycles for the entire lifetime of the instance until termination.
* **Instance States & Billing:**
  * **`Running`:** Instance is active; billed per second/hour.
  * **`Stopped`:** Compute billing stops, data on attached EBS volumes persists, and User Data does **not** re-run when started again.
  * **`Terminated`:** Instance is permanently destroyed. By default, the root EBS volume has **`Delete on Termination = Yes`** (deleted automatically with the instance), whereas additional attached EBS volumes default to `No`.
* **AWS Free Tier (EC2):** Includes `750 hours/month` of `t2.micro` (or `t3.micro` in regions without `t2.micro`) plus `30 GB` of EBS General Purpose (`gp2`/`gp3`) storage per month for the first 12 months.

## 3. CLI Commands / LocalStack Lab

```powershell
# 1. Create an SSH Key Pair (.pem) and save the private key locally
awslocal ec2 create-key-pair --key-name EC2Tutorial --query 'KeyMaterial' --output text | Out-File -Encoding ascii -FilePath EC2Tutorial.pem

# 2. Create a Security Group and allow SSH (22) & HTTP (80) from anywhere
$sgId = awslocal ec2 create-security-group --group-name launch-wizard-1 --description "Allow SSH and HTTP" --query 'GroupId' --output text
awslocal ec2 authorize-security-group-ingress --group-id $sgId --protocol tcp --port 22 --cidr 0.0.0.0/0
awslocal ec2 authorize-security-group-ingress --group-id $sgId --protocol tcp --port 80 --cidr 0.0.0.0/0

# 3. Create the EC2 User Data bootstrap script (installs Apache httpd & serves Private IP)
@'
#!/bin/bash
yum update -y
yum install -y httpd
systemctl start httpd
systemctl enable httpd
echo "<h1>Hello World from $(hostname -f)</h1>" > /var/www/html/index.html
'@ | Set-Content -Path user-data.sh -Encoding UTF8

# 4. Launch the EC2 instance (Amazon Linux 2, t2.micro, 8GB gp2 root volume)
$instanceId = awslocal ec2 run-instances `
  --image-id ami-0c55b159cbfafe1f0 `
  --instance-type t2.micro `
  --key-name EC2Tutorial `
  --security-group-ids $sgId `
  --user-data file://user-data.sh `
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=MyFirstInstance}]' `
  --query 'Instances[0].InstanceId' --output text

# 5. Inspect Instance State, Public IP, and Private IP
awslocal ec2 describe-instances --instance-ids $instanceId `
  --query 'Reservations[0].Instances[0].{ID:InstanceId,State:State.Name,PublicIP:PublicIpAddress,PrivateIP:PrivateIpAddress}' --output table

# 6. Lifecycle Management: Stop -> Start (observe Public IP change) -> Terminate
awslocal ec2 stop-instances --instance-ids $instanceId
awslocal ec2 start-instances --instance-ids $instanceId
awslocal ec2 terminate-instances --instance-ids $instanceId
```

## 4. Security, IAM & Key Exam Limits
* **Required Permissions:** `ec2:RunInstances`, `ec2:DescribeInstances`, `ec2:StopInstances`, `ec2:TerminateInstances`, `iam:PassRole` (when attaching an Instance Profile).
* **Critical Exam / Architecture Points:**
  * **User Data runs once at first boot as `root`:** Classic exam trap—if an instance is stopped and started again, User Data does **not** re-execute by default.
  * **Instance Store vs. EBS:** Instance Store is physically attached to the host hardware (ephemeral), whereas EBS is network-attached (persistent).
  * **Public IP changes on Stop/Start:** Stopping and starting an EC2 instance changes its Public IPv4 address while keeping its Private IPv4 address intact. (Rebooting inside the OS keeps both IPs unchanged).
  * **EBS Delete on Termination:** Root EBS volumes are deleted by default when an instance is terminated; extra attached volumes survive unless configured otherwise.

## 5. Quick Comparison (Key Differences vs. Similar Services)
| Feature | 03-EC2 | Alternative (Lambda / Serverless) |
| :--- | :--- | :--- |
| **Control & OS Access** | Full root/admin OS control (Linux, Windows, macOS) | No OS access; code-only execution |
| **Billing Model** | Pay per second/hour while running | Pay strictly per request & execution ms |
| **Ideal Use Case** | Long-running servers, custom runtimes, stateful apps | Event-driven tasks, short functions (<15 min) |
