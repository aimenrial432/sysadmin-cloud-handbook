# 03-EC2 (Amazon Elastic Compute Cloud)

## 1. Executive Summary (What is it & Why use it?)
* **One-Sentence Definition:** **Amazon EC2 (Elastic Compute Cloud)** is AWS's core **Infrastructure as a Service (IaaS)** offering that lets you rent resizable virtual servers (EC2 instances) on demand in the cloud.
* **Primary Use Case:** Hosting applications, web servers, backend APIs, batch processing, and custom workloads requiring full OS-level control (Linux, Windows, or macOS).
* **Scope / Responsibility Model:**
  * **Scope:** **Regional** service (instances are launched inside a specific Availability Zone within a Region).
  * **Shared Responsibility:** AWS manages the physical host, hypervisor, and underlying network; **you** manage the guest OS, patches, applications, Security Groups, and data.

## 2. Key Concepts & Architecture

### A. EC2 Ecosystem Components (High-Level)
EC2 is more than just virtual machines—it encompasses a full compute ecosystem:
* **EC2 Instances:** On-demand virtual servers rented from AWS.
* **EBS (Elastic Block Store):** Persistent virtual hard drives attached over the network.
* **ELB (Elastic Load Balancer):** Distributes incoming network traffic across multiple EC2 instances.
* **ASG (Auto Scaling Group):** Automatically scales the number of EC2 instances in or out based on demand.

### B. Instance Configuration Options (Sizing & Hardware)
When provisioning an EC2 instance, you customize:
* **Operating System (AMI):** **Linux** (most common), **Windows**, or **macOS**.
* **Compute & Memory:** Number of virtual CPUs (**vCPU**) and amount of **RAM**.
* **Storage Type:**
  * *Network-attached:* **EBS** (block storage) or **EFS** (shared network file system).
  * *Hardware-attached (ephemeral):* **EC2 Instance Store** (physically attached to the host server for ultra-high IOPS).
* **Networking:** Network card speed (bandwidth) and Public IP assignment.
* **Firewall Rules:** **Security Groups** controlling inbound and outbound traffic.

### C. Bootstrapping with EC2 User Data
* **Definition:** Passing a startup script (**EC2 User Data**) to automate tasks when an instance launches.
* **Execution Behavior:**
  * Runs **only once**—strictly during the **first boot** of the instance (never re-runs on subsequent reboots).
  * Executes with **`root` privileges** (`sudo` rights by default), so commands do not need `sudo` prepended.
* **Common Tasks:** Installing OS updates, installing software packages (e.g., Apache/Nginx), downloading files from the internet, or configuring services.
* **Trade-off:** Adding heavy tasks to User Data increases total instance boot time.

## 4. Security, IAM & Key Exam Limits
* **Required Permissions:** `ec2:RunInstances`, `ec2:DescribeInstances`, `ec2:StopInstances`, `ec2:TerminateInstances`, `iam:PassRole` (when attaching an Instance Profile).
* **Critical Exam / Architecture Points:**
  * **User Data runs once at first boot as `root`:** Classic exam trap—if an instance is stopped and started again, User Data does **not** re-execute by default.
  * **Instance Store vs. EBS:** Instance Store is physically attached to the host hardware (ephemeral), whereas EBS is network-attached (persistent).

## 5. Quick Comparison (Key Differences vs. Similar Services)
| Feature | 03-EC2 | Alternative (Lambda / Serverless) |
| :--- | :--- | :--- |
| **Control & OS Access** | Full root/admin OS control (Linux, Windows, macOS) | No OS access; code-only execution |
| **Billing Model** | Pay per second/hour while running | Pay strictly per request & execution ms |
| **Ideal Use Case** | Long-running servers, custom runtimes, stateful apps | Event-driven tasks, short functions (<15 min) |
